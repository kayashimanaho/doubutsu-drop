進化チャートとスコア設計で悩んだこと

2026年8月1日

どうぶつドロップの開発で最も時間をかけたのは物理エンジンの調整ではなく、「どうぶつを何種類にするか」「合体したときに何点もらえるか」というゲームデザインの根幹部分でした。試行錯誤の過程を振り返ります。

進化チャート：なぜ10種類にしたか

最初のプロトタイプでは7種類のどうぶつで試しました。「ひよこ・ネコ・イヌ・コアラ・パンダ・ゾウ・ドラゴン」というラインナップです。しかしプレイしてみると、ゲームの時間軸が短すぎるという問題がありました。7種類だと盤面の密度が増すのが早く、序盤の「小さなどうぶつを積み上げる」楽しさを味わうまもなくゲームオーバーになってしまいます。

逆に12種類以上に増やすと今度は最大サイズのどうぶつが大きくなりすぎて、盤面に2体以上入らなくなります。物理ゲームとして見たとき、最大サイズのどうぶつが画面幅の約3分の1を占める状態が望ましく、それを満たす段階数として10が適切でした。

動物の選定にも悩みました。条件は3つです。

  • 子どもが名前を知っている動物（認知負荷を下げる）
  • 大きさのイメージが直感的に伝わる順番（小→大の成長感）
  • 最後に「伝説・最強」のイメージで終わること（到達感の演出）

この3条件から「ひよこ→ウサギ→ネコ→イヌ→コアラ→パンダ→ライオン→ゾウ→きょうりゅう→ドラゴン」というチャートになりました。コアラとパンダの位置は何度か入れ替えましたが、「パンダの方が少し大きい」という直感とサイズ設定（コアラr=58、パンダr=70）が一致したため現在の順序に落ち着いています。

スコア設計：なぜ三角数を選んだか

最初の失敗：等差スコア

最初はシンプルに「合体するたびに10点」「段階が上がるたびに+10点」という等差設計にしていました。ひよこ合体で10点、ウサギ合体で20点……という具合です。しかしこれはドラゴンを作るインセンティブが弱いという問題を生みました。

等差設計だとドラゴン（10段階目・100点）を1体作るより、ひよこ（1段階目・10点）を10回合体させる方が同じ点数で盤面を圧迫しません。上を目指すより小さなどうぶつを連発した方が効率的になってしまうのです。

指数スコアの試行と問題

次に「段階ごとに2倍」という指数設計を試しました。ひよこ1点・ウサギ2点・ネコ4点……ドラゴン512点。しかし今度は逆の問題が起きました。序盤のスコアがほぼ0に近くなり、大きなどうぶつを作るまでゲームが始まった気がしないのです。プレイヤーがスコアの伸びを感じるのはライオン（7段階目・64点）あたりからになってしまい、それまでの体験がフラットすぎました。

三角数：程よい加速度

最終的に採用したのが三角数（triangular number）です。三角数とは 1, 3, 6, 10, 15, 21, 28, 36, 45, 55 … という数列で、n番目の値は n×(n+1)÷2 で求まります。

段階どうぶつ合体時ポイント（三角数）等差との比較
1🐥 ひよこ1 pt10 pt（等差）
2🐰 ウサギ3 pt20 pt
3🐱 ネコ6 pt30 pt
5🐨 コアラ15 pt50 pt
7🦁 ライオン28 pt70 pt
9🦕 きょうりゅう45 pt90 pt
10🐉 ドラゴン55 pt100 pt

等差に比べて序盤のポイントは小さいですが、段階が上がるにつれて差が縮まり、終盤では逆転します。重要なのは「大きなどうぶつを1体作る方が、小さなどうぶつを量産するよりも明確に効率が良い」という戦略的優位性が数式に組み込まれている点です。

また、三角数はプログラムコードが非常にシンプルです。

// n段階目のポイント = n×(n+1)÷2 // どうぶつ定義の配列に直書き const A = [ { name:'ひよこ', r:20, pts: 1 }, // 1×2÷2 { name:'ウサギ', r:28, pts: 3 }, // 2×3÷2 { name:'ネコ', r:37, pts: 6 }, // 3×4÷2 // ... { name:'ドラゴン',r:128,pts: 55 }, // 10×11÷2 ];

ゲームオーバー条件：2秒の猶予

ゲームオーバーの条件は「デンジャーラインを超えたどうぶつが存在する」ではなく、「デンジャーラインを超えた状態が2秒以上継続する」にしています。この違いが意外に重要でした。

落下直後のどうぶつは一瞬デンジャーラインを超えることがあります。瞬間判定にすると、落とした瞬間にゲームオーバーになる理不尽な状況が生まれます。2秒の猶予を設けることで「落としたけど合体でうまく収まった」という逆転体験が生まれ、プレイの緊張感が高まりました。

⚠️ 没になった要素：ボム

開発途中、デンジャーラインを超えたどうぶつを消す「ボム」アイテムを実装していました。盤面が厳しくなったときの救済手段として設けたのですが、実際にプレイしてみるとボムの出現頻度の調整が非常に難しいことが分かりました。多すぎると難易度が下がりすぎ、少なすぎると存在に気づかないまま終わります。結局「ドラゴン全消し」という自然な逆転手段を強化する方向で代替し、ボムは削除しました。

ドラゴン全消しボーナスの設計

ドラゴン2体の合体で盤面を全消しする機能は、ゲームバランス上の「救済手段」として設計しました。合体パズルの後半は盤面が詰まりやすく、そのままゲームオーバーになるしかない局面が増えます。ドラゴン全消しがあることで「今は苦しくてもドラゴンを育てれば逆転できる」という長期目標が生まれ、諦めずにプレイが続けられるようになりました。

ボーナス点数は300点に設定しています。これはドラゴン1体を作るために必要なポイント総量（全どうぶつのポイントを一度ずつ獲得すると約200点）より少し多い数字です。全消しで一気に逆転できるほど大きくはなく、しかし「やってよかった」と感じられる程度の存在感を持つよう調整しました。

💡 まとめ：ゲームデザインで学んだこと
  • 進化チャートの種類数は「ゲームの時間軸」と「最大サイズの視認性」で決まる
  • 等差スコアは直感的だが「大きなどうぶつを目指す理由」が生まれにくい
  • 三角数は「序盤の楽しさ」と「終盤の戦略性」を両立できる加速度を持つ
  • ゲームオーバー判定に猶予を持たせると理不尽感が激減する
  • 救済手段はアイテムより「ゲームの目標そのもの」に内包させると自然になる

スコア計算の具体的な数値は攻略ガイドのスコア計算セクションで確認できます。物理エンジンの実装についてはMatter.jsをブラウザゲームに採用した理由をご覧ください。
